4. **Відповідність прототипам:** точні групи навігації, логотипи, оформлення всіх станів і перевірка обох тем у браузері.

## Що потрібно для деплою

1. Налаштувати `backend/.env` або середовище pm2 за `backend/example.env`:

   ```dotenv
   NODE_ENV=production
   PORT=5000
   FRONTEND_URL=https://kse-ai-analyzer.biz.ua
   LLM_PROVIDER=anthropic
   LLM_MODEL=claude-haiku-5-5
   ANTHROPIC_API_KEY=<ключ із доступом до моделі>
   MONGODB_URI=<бойова база>
   JWT_SECRET=<секрет>
   ```

   OpenAI-ключ для цього провайдера не потрібен. Для першого адміністратора — власні `ADMIN_EMAIL`/`ADMIN_PASSWORD`; для листів акаунта — SMTP або Gmail. Чинний JWT-секрет слід зберегти, якщо потрібно зберегти поточні сесії.

2. Відновити підключення MongoDB, зробити backup БД і `backend/uploads/`. Оновити серверний checkout до злитого `main`. Використати Node.js 24 (поточне середовище) та встановити залежності через `npm ci` у backend і frontend. LibreOffice потрібен для вхідних `.doc`.

3. Якщо бойова база ще не мігрована на v5, виконати з кореня репозиторію спочатку `--dry-run`, потім застосування для кожного скрипта в цьому порядку:

   ```bash
   node scripts/migrate-v5-policies.js --dry-run
   node scripts/migrate-v5-policies.js
   node scripts/migrate-v5-references.js --dry-run
   node scripts/migrate-v5-references.js
   node scripts/migrate-v5-state.js --dry-run
   node scripts/migrate-v5-state.js
   node scripts/migrate-v5-offerings.js --dry-run
   node scripts/migrate-v5-offerings.js
   ```

   Обрати правильний `--default-edition` для старих силабусів (типово MBA28). Міграція state видаляє старі вихідні файли й пропозиції v4, тому backup має передувати їй. Якщо v5 вже мігрований, звірити стан, а не вважати всі кроки новими. У production `autoIndex` вимкнений: створити відсутні індекси нових моделей, зокрема унікальний індекс CourseOffering, через `createIndexes()`.

4. Зібрати frontend із production API та вимкненими моками:

   ```bash
   cd frontend
   REACT_APP_API_URL=/api REACT_APP_USE_MOCKS=0 npm run build
   ```

   Опублікувати `build` там, де nginx може читати файли (наприклад, окремий каталог `/var/www` з відповідним `root`), або налаштувати точкові права доступу до поточного шляху. Одного дозволу на `/home/ubuntu` недостатньо: вкладений каталог проєкту також закритий.

5. Перезапустити `ai-syllabus-analyzer` через pm2 з оновленим середовищем та правильним cwd; перевірити `/health` **з `dbConnected: true`**, головну сторінку, login, обидва треки, реальний виклик Haiku і завантаження DOCX. Перевірити `nginx -t` перед його перезавантаженням.

Ця операція зливає код; бойову БД, pm2 та nginx під час злиття не змінено.
